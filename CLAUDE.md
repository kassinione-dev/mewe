# MeWe

Telegram Mini App для студенческих мероприятий ДВФУ. Стек и структура — в `README.md`.
Общение — на русском.

## Ветки и деплой

- Пуш в `main` деплоится на сервер после зелёного CI (`.github/workflows/ci.yml` → `deploy.yml`):
  `git reset --hard`, пересборка, бэкап БД, `alembic upgrade head`. Сервер тестовый, прода пока нет.
- Каждая задача — в своей ветке: `fix/…`, `refactor/…`, `feature/…`. Название описывает проблему,
  а не способ решения. После мержа ветку удаляем.
- Ветки вливаем в `main` локально, а пушим пачкой — чтобы не пересобирать контейнеры по нескольку раз.
  Пушить только когда об этом попросили.
- `feature/roles-reports` — отложенная работа, в `main` не вливать (две головы миграций, см. `TODO.md`).

## Проверки перед коммитом

- `uvx ruff check src tests` должен проходить.
- `uv run pyright` (режим `strict`) должен проходить. `# pyright: ignore[правило]` — только для дыр
  в типах библиотек и с комментарием, почему; свой код типизируем (модели — `Mapped[...]`, ответы — `TypedDict`).
- `# noqa` — только с пониманием, почему правило здесь неприменимо (DTZ-предупреждения
  когда-то заглушили вместо исправления naive-дат).
- `uv run pytest` должен проходить (нужна тестовая MySQL, см. README). Новое бизнес-правило — новый тест.

## Бэкенд: архитектура

Слои: `routes/` → `services/` → `repositories/` → `models.py`, зависимости только вниз и только на соседний слой.

- Роуты: разбор запроса, вызов сервиса, сериализация и код ответа. В репозитории и модели напрямую не ходят.
- Сервисы: бизнес-правила и `commit`. Не знают про HTTP — никаких `request`, `session`, `jsonify`.
- Репозитории: только запросы, без правил и без `commit`. Запросы — `select()` + `db.session`, не `Model.query`.
- Тело запроса разбирает роут: `parse_json_body(Schema)` из `api.py` → модель Pydantic из `schemas/`.
  Сервис получает уже типизированные данные, а не `payload: dict`. Схема проверяет формат (тип, длина,
  дата с поясом), сервис — правила, которым нужны время или БД (дата в будущем, категория существует, кулдаун).
- Сессия и `login_required` — в `src/app/auth.py`; «запрос к API или к странице» — `is_api_request()` в `src/app/api.py`.
- Результаты из нескольких значений: кортеж для 2–3 полей, иначе `@dataclass(frozen=True)` (пример — `services/pagination.py`).
- Внутренние функции модуля — с `_` в начале.
- Роуты импортируют сервис модулем (`from ..services import event_service` → `event_service.join_event(...)`),
  поэтому роут и сервис могут называться одинаково — без псевдонимов `as ..._service`.
- Имена по слою: роуты — по действию эндпоинта (`list_events`, `create_session`); сервисы — бизнес-действия
  (`authenticate`, `join_event`); репозитории — `get_…` (один объект или `None`, список), `find_…` (поиск
  с фильтрами), `count_…`, `…_exists`.
- Префикс URL — в `Blueprint(url_prefix=...)`, в `@route` только остаток пути.

## Бэкенд: ошибки

- Ошибка клиента — наследник `AppError` из `exceptions.py` (`ValidationError` → 400 и т.д.).
  Встроенные `ValueError`/`TypeError` означают баг в нашем коде и дают 500.
- Запросы под `/api/` получают ошибки в JSON, страницы — `templates/error.html` (`errors.py`).

## Время

- Внутри всё в UTC: колонки — `UTCDateTime` (`db_types.py`), текущее время — `datetime.now(UTC)`,
  `datetime.utcnow()` не использовать. Naive-даты при записи в БД падают с `ValueError` — это намеренно.
- Клиент отправляет дату в ISO с поясом (`toISOString()`), без пояса API отвечает 400.
- Форматирование для человека — только на клиенте, сервер отдаёт ISO.

## Миграции

- БД одна — на тестовом сервере; миграция применяется сама при пуше в `main`.
- `downgrade()` пишем всегда и проверяем откат на сервере (`downgrade -1` → `upgrade head`).
- Миграции данных объясняют свои допущения в docstring.
- В миграциях — обычные типы `sa.*`, не импорты из кода приложения.
- Проверять, что голова одна: `alembic heads`.

## Безопасность

- `LIKE` с пользовательским вводом — только `icontains(..., autoescape=True)`; для равенства — `==`, не `ilike`.
- Пользовательский текст на фронте выводить через `textContent`, не `innerHTML`.
- Проверку `Origin` для изменяющих запросов к `/api/` (`before_request` в `__init__.py`) не ослаблять:
  cookie сессии вынужденно `SameSite=None`.

## Фронтенд: архитектура

Без сборщика: нативные ES-модули и обычный CSS, файлы отдаются как есть.

```
static/css/  tokens.css (палитра) → base.css → components/*.css → pages/*.css
static/js/   boot/        классические скрипты в <head>, выполняются до отрисовки
             core/        auth, http (requestJson), dom (h, icon), format, toast, storage
             api/         все пути API — только здесь
             components/  modal, event-card, event-detail, category-filter, event-form, empty-state
             pages/       одна точка входа на страницу, подключается в {% block scripts %}
templates/partials/       разметка, общая для нескольких страниц
```

- Зависимости: `pages` → `components` → `api`/`core`. Компоненты не знают о странице — общаются колбэками.
- Запросы к API — только через `api/*` → `core/http.js` (`requestJson` бросает `ApiError`), не `fetch` напрямую.
- Элементы — через `h()` из `core/dom.js`; пользовательский текст попадает в DOM только как текст.
- Модальные окна — `components/modal.js`: разметка `.modal` + `[data-modal-close]`, состояние `.is-open`.
- Стили привязываем к классам, не к `id`. Цвета — только через переменные из `tokens.css`.
- Иконки — Material Symbols: `icon()` из `templates/macros.html` и `core/dom.js`. Шрифт грузится подмножеством,
  поэтому новое имя иконки (в том числе для категории в БД) сначала добавляется в `src/app/icons.py`,
  иначе вместо иконки появится текст.
- Стили страницы подключаются в `{% block styles %}` после общих.
- Перед коммитом фронтенда — сравнить скриншоты до/после и прогнать сценарии в браузере (Playwright).

## Фронтенд и тема

- Тема: `static/js/boot/theme.js` (в `<head>`, до отрисовки) ставит `data-theme` и красит шапку Telegram;
  режим `auto`/`light`/`dark` хранится в `localStorage` и Telegram `CloudStorage`. Интерфейс к ней —
  `window.MeWeTheme`, переключатель — в своём профиле (`components/theme-switcher.js`).
- Цвета темы Telegram (`themeParams`) не используем — только своя палитра в `static/css/tokens.css`.
- `--accent` — текст, иконки, обводки; `--accent-fill` — заливка под белым текстом.

Владелец проекта изучает бэкенд: по бэкенду объяснять подробно и давать писать код самому, если не просит
сделать за него. Фронтенд — обычно делает Claude.

## Коммиты

Сообщения коммитов — по [Conventional Commits](https://www.conventionalcommits.org/):
`<тип>: <что сделано>` или `<тип>(<область>): <что сделано>`.

- На английском, в повелительном наклонении, с маленькой буквы, без точки в конце:
  `fix(search): escape like wildcards`
- Не подстраиваться под стиль последних коммитов в истории — часть из них написана без типа.

| Тип | Когда |
|---|---|
| `feat` | новая возможность для пользователя |
| `fix` | исправление бага, включая UI и безопасность |
| `refactor` | перестройка кода без изменения поведения |
| `perf` | ускорение |
| `test` | тесты |
| `ci` | GitHub Actions, деплой |
| `build` | Dockerfile, зависимости |
| `chore` | всё остальное (`.gitignore`, конфиги) |
| `docs` | документация |

- `style` — только форматирование кода, не изменения внешнего вида (это `feat` / `fix`).
- `refactor` не меняет поведение; если поведение меняется — это `feat` или `fix`.
- Если коммиту подходят несколько типов — его стоит разбить.
- Область по желанию: `auth`, `search`, `profile`, `events`, `migrations` и т.п.
